# ☘ آیهٔ روز (Aya of Day)

**هر روز یک آیهٔ قرآن، همراه با ترجمهٔ آیت‌الله قرائتی، به‌صورت خودکار در تلگرام، بله، ایتا، روبیکا و توییتر (X) منتشر می‌شود.**

اجرا روی **Cloudflare Workers** • پایگاه‌داده **D1** • داشبورد مدیریتی فارسی

🌐 **[quran.zareshahi.ir](https://quran.zareshahi.ir)**

</div>

---

## ✨ امکانات

- 🕌 **انتخاب آیه** به سه روش: فهرست منتخب (حدود ۲۰۰ آیهٔ برگزیده)، ترتیبی، یا کاملاً تصادفی — به‌علاوهٔ امکان تعریف فهرست دلخواه.
- 📖 متن عربی با رسم‌الخط عثمانی + ترجمهٔ فارسی **آیت‌الله محسن قرائتی** (`fa.gharaati`) از سرویس [alquran.cloud](https://alquran.cloud).
- 📡 **۵ کانال هم‌زمان**: تلگرام، بله، ایتا، روبیکا، توییتر/X (با پشتیبانی از رشته‌توییت برای متن‌های بلند).
- ⏰ **کران‌جاب** هر ۵ دقیقه؛ ارسال دقیقاً در ساعت تنظیم‌شده به وقت تهران با قفل روزانه برای جلوگیری از ارسال تکراری.
- 🖥️ **داشبورد مدیریتی** فارسی و راست‌چین: تنظیمات، مدیریت توکن کانال‌ها، پیش‌نمایش پیام، ارسال فوری، تاریخچهٔ ارسال‌ها و لاگ‌ها.
- 🔐 توکن‌های کانال‌ها با **AES-GCM** رمزنگاری و در D1 ذخیره می‌شوند؛ رمز مدیر با **PBKDF2 (۱۰۰٬۰۰۰ دور، SHA-256)** هش می‌شود.
- 💸 کاملاً روی پلن رایگان Cloudflare اجرا می‌شود؛ بدون سرور و بدون هزینهٔ ماهانه.

## 🏗️ معماری

```
Cloudflare Cron (*/5 * * * *)
        │
        ▼
   Worker (src/worker.js)  ──►  api.alquran.cloud   (دریافت آیه + ترجمه)
        │                 ──►  Telegram / Bale / Eitaa / Rubika / X
        │
        ▼
   D1 Database (settings, channels, sends, deliveries, logs, daily_locks)
        │
        ▼
   داشبورد در quran.zareshahi.ir
```

ورکر یک فایل مستقل است و رابط کاربری را خودش سرو می‌کند؛ فایل‌های `public/app.css` و `public/app.js` از طریق مسیر `/static/*` از jsDelivr پراکسی و یک ساعت در لبه کش می‌شوند (با فالبک به raw.githubusercontent.com).

### ساختار پروژه

```
src/worker.js              منطق کامل ورکر + API + قالب HTML داشبورد
public/app.css             استایل داشبورد (تم تیره، فونت وزیرمتن)
public/app.js              اسکریپت سمت کاربر داشبورد
db/schema.sql              اسکیمای D1
wrangler.jsonc             پیکربندی Cloudflare
docs/CHANNELS.md           راهنمای گرفتن توکن هر پیام‌رسان
.github/workflows/deploy.yml   انتشار خودکار با هر push روی main
```

## 🚀 راه‌اندازی

### ۱. نصب

```bash
git clone https://github.com/0xzare/aya-of-day-worker.git
cd aya-of-day-worker
npm install
```

### ۲. ساخت پایگاه‌داده

```bash
npx wrangler d1 create aya-of-day
# شناسهٔ خروجی را در wrangler.jsonc جایگزین کنید
npm run db:init
```

### ۳. تنظیم رمزها

```bash
npx wrangler secret put ADMIN_PASSWORD     # رمز ورود به داشبورد
npx wrangler secret put SESSION_SECRET     # رشتهٔ تصادفی برای امضای نشست
npx wrangler secret put ENCRYPTION_KEY     # رشتهٔ تصادفی برای رمزنگاری توکن‌ها
```

> ⚠️ تغییر `ENCRYPTION_KEY` باعث می‌شود توکن‌های ذخیره‌شده غیرقابل رمزگشایی شوند و باید دوباره وارد شوند.

### ۴. انتشار

```bash
npm run deploy
```

برای انتشار خودکار از گیت‌هاب، این دو Secret را در تنظیمات مخزن اضافه کنید: `CLOUDFLARE_API_TOKEN` و `CLOUDFLARE_ACCOUNT_ID`.

## 🎛️ کار با داشبورد

وارد <https://quran.zareshahi.ir> شوید و با رمز مدیر وارد شوید.

| تب | کاربرد |
| --- | --- |
| نمای کلی | آیهٔ امروز، وضعیت کانال‌ها، زمان ارسال بعدی |
| کانال‌ها | ورود توکن‌ها، فعال/غیرفعال کردن و **تست ارسال** هر کانال |
| تنظیمات | ساعت ارسال، منطقهٔ زمانی، روش انتخاب آیه، هشتگ‌ها، پانویس، تغییر رمز |
| تاریخچه | فهرست ارسال‌ها و نتیجهٔ تفکیکی هر کانال |
| لاگ | رویدادها و خطاهای سامانه |

دکمه‌های بالای صفحه: **پیش‌نمایش** (بدون ارسال) و **ارسال فوری**.

راهنمای گرفتن توکن هر پیام‌رسان در [`docs/CHANNELS.md`](docs/CHANNELS.md) آمده است.

## 🔌 مسیرهای API

| مسیر | دسترسی | توضیح |
| --- | --- | --- |
| `GET /health` | عمومی | بررسی سلامت سرویس |
| `GET /api/today` | عمومی | آیهٔ امروز به‌صورت JSON |
| `POST /api/login` · `/api/logout` | عمومی | ورود و خروج |
| `GET /api/state` | مدیر | تنظیمات، کانال‌ها، آمار |
| `POST /api/settings` | مدیر | ذخیرهٔ تنظیمات |
| `POST /api/channels/:id` · `/api/test/:id` | مدیر | ذخیره و تست کانال |
| `GET /api/preview` · `POST /api/send-now` | مدیر | پیش‌نمایش و ارسال فوری |
| `POST /api/password` · `/api/unlock-today` | مدیر | تغییر رمز، آزادسازی قفل روز |

## ⏱️ زمان‌بندی

کران هر ۵ دقیقه اجرا می‌شود و فقط زمانی پیام می‌فرستد که ساعت محلی داخل بازهٔ تعریف‌شده (پیش‌فرض: ۲۰:۰۰ به وقت تهران با تحمل ۳۰ دقیقه) باشد و آن روز هنوز ارسالی ثبت نشده باشد. منطقهٔ زمانی به‌صورت اختلاف دقیقه‌ای ذخیره می‌شود (ایران: `210` معادل UTC+03:30).
